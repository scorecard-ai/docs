---
title: "Vercel AI SDK"
description: "Trace every generateText, streamText, generateObject, streamObject, and embedding call in a Vercel AI SDK app by wrapping the ai module."
---

Wrap the [Vercel AI SDK](https://ai-sdk.dev) module once, and every call through the wrapper is traced, including streaming and tool calls.

## Set up

<Steps>
  <Step title="Install the Scorecard SDK">
    ```bash
    npm install scorecard-ai
    ```
  </Step>
  <Step title="Set your API key and project ID">
    ```bash
    export SCORECARD_API_KEY="ak_..."
    export SCORECARD_PROJECT_ID="314"
    ```
  </Step>
  <Step title="Wrap the ai module">
    Create the wrapper in one module and use it wherever you call the model:

    ```typescript lib/ai.ts
    import * as ai from "ai";
    import { wrapAISDK } from "scorecard-ai";

    export const aiSDK = wrapAISDK(ai, { serviceName: "my-app" });
    ```

    ```typescript app/route.ts
    import { openai } from "@ai-sdk/openai";
    import { aiSDK } from "./lib/ai";

    const { text } = await aiSDK.generateText({
      model: openai("gpt-4o-mini"),
      prompt: "What is the capital of France?",
    });
    ```

    Replace imports such as `import { generateText } from "ai"` with calls on the wrapper. Type imports from `ai` can stay as they are.
  </Step>
  <Step title="View your traces">
    Run your app and open the project's **Records** page. Each call appears as a record within a minute. To group one request's calls into one record, open a parent span around it, as in [Group calls into one trace](/integrations/openai-anthropic#group-calls-into-one-trace).
  </Step>
</Steps>

## What's traced

The wrapper adds tracing to `generateText`, `streamText`, `generateObject`, `streamObject`, `embed`, and `embedMany`. Every other export passes through unchanged, so the wrapper works as a drop-in replacement for the `ai` module.

## Configuration

| Option | Default | Description |
| --- | --- | --- |
| `projectId` | `SCORECARD_PROJECT_ID` | The numeric project ID traces go to |
| `apiKey` | `SCORECARD_API_KEY` | Your Scorecard API key |
| `serviceName` | `ai-sdk-app` | The OpenTelemetry service name, for example one per environment |
| `serviceVersion` | none | Your app's version, to compare releases |
| `maxExportBatchSize` | `1` | Spans per export. Raise it for high-throughput servers. |
| `metrics` | `[]` | Metric IDs or plain-language descriptions. Descriptions become new metrics in the project. It doesn't score traces: use [Score Records](/features/records#score-records). |

`SCORECARD_TRACING_URL` overrides the OTLP endpoint.

## Use an existing OpenTelemetry setup

`wrapAISDK` uses its own tracer provider. If your app already registers one, for example with `@vercel/otel` in `instrumentation.ts`, skip the wrapper: add a Scorecard exporter to your provider, as in [OpenTelemetry](/integrations/opentelemetry#add-scorecard-to-an-existing-setup), and pass `experimental_telemetry: { isEnabled: true }` to each AI SDK call.

## Troubleshooting

<AccordionGroup>
  <Accordion title="SCORECARD_API_KEY is missing">
    Set the environment variable, or pass `apiKey` to `wrapAISDK`.
  </Accordion>
  <Accordion title="Traces don't appear">
    - Check that calls go through the wrapper, not functions imported directly from `ai`.
    - If your app already registers an OpenTelemetry provider, see [Use an existing OpenTelemetry setup](#use-an-existing-opentelemetry-setup).
    - In Next.js, create the wrapper in server code only.
  </Accordion>
</AccordionGroup>
