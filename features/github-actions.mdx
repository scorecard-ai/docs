There are two ways to run Scorecard evaluations in GitHub Actions:

- **Add a workflow** that runs your evaluation script on pull requests and on a schedule. This is the simplest option and works with any eval script.
- **Install the Scorecard GitHub app** to start runs of your real system from the Scorecard UI.

## Run your eval script in a workflow

<Steps>
  <Step title="Write an eval script">
    Start from the [Evaluation quickstart](/intro/sdk-quickstart) and point it at a saved testset with `testset_id`, so every run uses the same testcases.
  </Step>
  <Step title="Add secrets">
    In your repository, open **Settings → Secrets and variables → Actions** and add `SCORECARD_API_KEY`, plus any keys your agent needs, such as `OPENAI_API_KEY`.
  </Step>
  <Step title="Add the workflow">
    Create `.github/workflows/scorecard-eval.yml`:

    ```yaml .github/workflows/scorecard-eval.yml
    name: Scorecard eval

    on:
      pull_request:
      schedule:
        - cron: "0 6 * * *" # daily at 06:00 UTC
      workflow_dispatch:

    jobs:
      eval:
        runs-on: ubuntu-latest
        env:
          SCORECARD_API_KEY: ${{ secrets.SCORECARD_API_KEY }}
          SCORECARD_PROJECT_ID: "314"
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
        steps:
          - uses: actions/checkout@v4
          - uses: actions/setup-python@v5
            with:
              python-version: "3.12"
          - run: pip install -r requirements.txt
          - run: python eval.py
    ```

    For a TypeScript script, use `actions/setup-node@v4`, install with your package manager, and run the script with `node`.
  </Step>
</Steps>

Each run calls your agent once per testcase and the judge once per testcase per AI metric, so 50 testcases with 2 AI metrics make 100 judge calls on every pull request. Add a `paths:` filter under `pull_request` to run only when your agent's code changes.

### Fail the build on a regression

`run_and_evaluate` returns before scoring finishes. To gate a pull request, add this to the end of `eval.py`, after `run_and_evaluate`. It waits for scoring, then fails the job if fewer than 90% of scores pass:

```python
import sys
import time


def pass_rate(run_id: str, timeout_s: int = 600) -> float:
    """Wait for scoring to finish, then return the share of Boolean scores that passed."""
    deadline = time.time() + timeout_s
    while scorecard.runs.get(run_id).status != "completed":
        if time.time() > deadline:
            raise TimeoutError("Scoring didn't finish in time")
        time.sleep(10)

    scores = [s.score for record in scorecard.records.list(run_id) for s in record.scores]
    passed = sum(1 for score in scores if score.get("binaryScore") is True)
    return passed / len(scores) if scores else 0.0


rate = pass_rate(run["id"])
print(f"Pass rate: {rate:.0%}")
sys.exit(0 if rate >= 0.9 else 1)
```

This example assumes Boolean metrics; for Integer metrics, count `intScore` values at or above your threshold. Runs with human metrics stay pending until reviewers grade them, so gate on AI and heuristic metrics only.

## Use the Scorecard GitHub app

Set it up once per repository:

<Steps>
  <Step title="Connect your repository">
    Open [GitHub App Setup](https://app.scorecard.io/configure-github), install the app, and select a repository and branch.
  </Step>
  <Step title="Choose when runs start">
    Choose **When a user kicks off a test run from the Scorecard UI**. For nightly or pull request runs, use the [workflow above](#run-your-eval-script-in-a-workflow); the app's workflows for those need manual fixes.
  </Step>
  <Step title="Merge the setup pull request">
    Scorecard opens a pull request that adds `.github/workflows/scorecard-eval.yml`, `run_tests.py`, and `requirements.txt`. Before merging, edit `run_system` in `run_tests.py` to call your agent, update `scorecard-ai` in `requirements.txt` to the latest version, and make sure the repository has a `SCORECARD_API_KEY` secret.
  </Step>
</Steps>

To start a run from the UI, open **Kickoff Run**, choose a testset and metrics, select the **GitHub** run environment, optionally pick a system version, and click **Run Tests**. **View dispatch history** lists past dispatches, and active runs show their workflow status.

<Accordion title="The generated workflow">
  The app's workflow reads the testset, metrics, and system version from the dispatch and passes them to `run_tests.py` as environment variables:

  ```yaml scorecard-eval.yml
  name: Scorecard Evaluation Workflow

  on:
    workflow_dispatch:
      inputs:
        project_id:
          description: Project ID
          required: true
        testset_id:
          description: Testset ID
          required: true
        metric_ids:
          description: Metric IDs
          required: false
        system_version_id:
          description: System Version ID
          required: false
    repository_dispatch:
      types: start-evaluation

  permissions:
    contents: read

  jobs:
    evaluation-test:
      runs-on: ubuntu-latest
      steps:
        - uses: actions/checkout@v4
        - uses: actions/setup-python@v5
          with:
            python-version: "3.12"
        - name: Install dependencies
          run: |
            python -m pip install --upgrade pip
            pip install -r requirements.txt
        - name: Run test
          env:
            SCORECARD_API_KEY: ${{ secrets.SCORECARD_API_KEY }}
            PROJECT_ID: ${{ github.event.inputs.project_id || github.event.client_payload.project_id || env.DEFAULT_PROJECT_ID }}
            TESTSET_ID: ${{ github.event.inputs.testset_id || github.event.client_payload.testset_id || env.DEFAULT_TESTSET_ID }}
            METRIC_IDS: ${{ github.event.inputs.metric_ids || github.event.client_payload.metric_ids || env.DEFAULT_METRIC_IDS }}
            SYSTEM_VERSION_ID: ${{ github.event.inputs.system_version_id || github.event.client_payload.system_version_id || env.DEFAULT_SYSTEM_VERSION_ID }}
          run: python3 run_tests.py
  ```
</Accordion>
