A **prompt** is a set of messages and a model, stored and versioned in Scorecard. Use prompts to test a single model call on a testset without writing code. Find them under **Advanced → Prompts** in your project.

## Create a prompt

1. Click **New Prompt** and give it a name and description. Prompts are visible to everyone in your organization.
2. Pick a model. The list shows models from providers you've added a key for. See [Model providers](/features/custom-provider).
3. Write the messages. Set each message's role to **System**, **User**, or **Assistant**, and click **+ Add Message** for more turns.
4. Click **Save Prompt**.

## Insert testcase fields

Prompt templates use Jinja. Each input field of the testcase is available by name, and `{{ allInputs }}` holds all of them as JSON:

```jinja
You are a helpful customer service assistant for {{ product_name }}.

Customer message: {{ customer_message }}
{% if customer_tier == "premium" %}This is a premium customer.{% endif %}
```

<Note>
  Prompt templates reference fields directly (`{{ customer_message }}`). Metric templates use `{{ inputs.customer_message }}` instead, because they also see outputs and expected values.
</Note>

## Versions

Saving a new prompt creates its first version. On the prompt's page, each **Save Changes** adds another, listed under **Prompt Versions**. Check **Publish this version to production** when saving, or click **Publish** on any version later, to mark it as the production version. Exactly one version is in production at a time. **Copy Prompt ID** copies a version's ID for use in code.

Temperature, maximum tokens, and top-p use the provider's defaults unless you set them in code. See [Manage prompts from code](#manage-prompts-from-code).

## Test a prompt on a testset

Before publishing a version, run it on a testset:

1. Open **Kickoff Run** from the sidebar (under **Advanced** in newer organizations), the Records page, or a testset's menu.
2. Choose the testset, the prompt version, and the metrics.
3. Under **Run Environment**, keep **Scorecard** and start the run.

Scorecard sends each testcase through the prompt and saves the model's reply as the `response` output, so metrics read it as `{{ outputs.response }}`. See [Runs](/features/runs) for reading the results.

## Manage prompts from code

Prompts are [systems](/features/runs#systems-and-versions) whose versions each have a `promptTemplate` and a `modelName` in their config. These examples assume `scorecard = Scorecard()` and `PROJECT_ID` set to your project ID:

<CodeGroup>
```python Python
system = scorecard.systems.upsert(
    PROJECT_ID,
    name="Support reply",
    config={
        "modelName": "gpt-4o-mini",
        "promptTemplate": [
            {"role": "system", "content": "You are a helpful support assistant."},
            {"role": "user", "content": "{{ customer_message }}"},
        ],
    },
)

version = scorecard.systems.versions.upsert(
    system.id,
    name="Shorter replies",
    config={
        "modelName": "gpt-4o-mini",
        "maxTokens": 300,
        "promptTemplate": [
            {"role": "system", "content": "You are a helpful support assistant. Reply in two sentences."},
            {"role": "user", "content": "{{ customer_message }}"},
        ],
    },
)
```

```typescript TypeScript
const system = await scorecard.systems.upsert(PROJECT_ID, {
  name: "Support reply",
  config: {
    modelName: "gpt-4o-mini",
    promptTemplate: [
      { role: "system", content: "You are a helpful support assistant." },
      { role: "user", content: "{{ customer_message }}" },
    ],
  },
});

const version = await scorecard.systems.versions.upsert(system.id, {
  name: "Shorter replies",
  config: {
    modelName: "gpt-4o-mini",
    maxTokens: 300,
    promptTemplate: [
      { role: "system", content: "You are a helpful support assistant. Reply in two sentences." },
      { role: "user", content: "{{ customer_message }}" },
    ],
  },
});
```
</CodeGroup>

`systems.upsert` makes its config the production version. `systems.versions.upsert` adds a version without changing production. Optional config keys are `temperature`, `maxTokens`, and `topP`.
