The **Records** page lists every record in a project: traced conversations, results your code created with the SDK or API, and outputs from Kickoff Runs. Use it to find problems, score records with metrics, review them with your team, and export them.

## Search and filter

Type in the search box to match text in inputs, outputs, and expected values. Free-text search covers the last 30 days by default; switch it to **All time** when you need older records.

To filter on a field, type its name and a colon, then a value. Each filter becomes a pill you can edit or remove.

| Filter | Matches records |
| --- | --- |
| `status:` | With status `pending`, `completed`, or `error` |
| `source:` | Created by `trace`, `api`, `kickoff`, or `playground` (older records) |
| `metric_status:` | Where a metric passed, failed, or is pending, for example `metric_status:accuracy:fail` |
| `metric:` | Scored with a metric |
| `tag:` | With a tag. Repeat it to require several tags. |
| `assigned.to:` | Assigned to an organization member |
| `run.id:`, `testcase.id:`, `testset:`, `trace.id:` | From a run, testcase, testset, or trace |
| `system:` | Produced by a system version |
| `created.at:`, `created.by:` | Created in a time range, or by a member |
| `metadata:` | With trace metadata matching the text |
| `resource.<key>:` | With an OpenTelemetry resource attribute value |

**Quick Filters** has presets such as **My Recent Records**, **Source → Traces**, and common time ranges. **Assigned to Me** shows the records assigned to you.

A record's status reflects its scores: `error` if any score failed to compute, `pending` if any metric is still waiting for a score, and `completed` otherwise.

## Customize the view

- **Columns** toggles and reorders columns, including score columns for each metric, tags, assignees, annotations, system, and resource attributes.
- The **Overview** strip above the table holds widgets that follow the table's filters. **Add widget** offers **Assigned to** and one widget per metric. A metric widget shows the pass rate as a snapshot or over time, and **Scored by** limits it to one grader.
- **Records Analysis** highlights patterns in recent records, such as failure spikes or scoring anomalies. Click **Show matching records** to filter the table to an insight.

Your layout is saved for you. To share it, open the **⋯** menu and use **Column & Widget Layout**: **Save as project default…** sets the layout people see when they first open the project, and **Export to file** and **Import from file…** copy a layout between projects.

## Open a record

Click a row to open the details panel with the record's inputs, outputs, expected values, conversation, and scores, plus its tags, assignees, annotations, and attachments. Click **View Full Details** to open the full record page. For a record with a trace, it has these tabs:

| Tab | Shows |
| --- | --- |
| **Conversation** | The trace as a readable conversation: user turns, model replies, tool calls and results, and nested sub-agents. Failed tool calls are marked. |
| **Output** | Outputs your code recorded through the SDK, when the record has them. Highlight text to annotate it. |
| **Chat** | Ask questions about the trace in natural language. Pick the model, attach a skill (a zip with a `SKILL.md`) to guide the analysis, or add other records to compare them. |
| **Scores** | The record's scores with their reasoning and grader, when it has scores. Members see their own, admins', and automated scores. |
| **Attachments** | Files attached to the record's session. |
| **Debug** | The span tree, the details of each span, and a trace overview with duration, cost, tokens, and model. |

A record without a trace opens to its scores and its input, output, and expected fields.

## Score records

1. Select records with the checkboxes.
2. Click **Score Records** and choose one or more metrics.
3. Click **Score**.

Scoring uses the latest version of each metric and runs in the background. Completed human scores are never overwritten. The chosen metrics are added to each record's run, so other records in that run also show those metrics as pending until you score them.

To apply another metric to a single record, use **Add score...** in its **Scores** section. Click an existing score to edit it. See [Human review](/features/human-review) for grading by people.

## Tag, assign, and annotate

- **Tags:** add them in the details panel, or select records and use **Add tag…** and **Remove tag…** in the **⋯** menu. Click a tag chip in the table to filter by it.
- **Assignees:** admins can select records and click **Assign** to queue them for reviewers.
- **Annotations:** rate a record or a single step with thumbs up or down and a comment, or highlight text in an output to comment on that passage.

See [Human review](/features/human-review) for the full review workflow.

## Attachments

Files attached to a session through the [attachments API](/api-reference/initiate-attachment-upload) appear on the session's record: in the details panel, on the **Attachments** tab, and as clickable chips in the conversation wherever the agent mentions them. Images, PDFs, audio, and video preview inline, as do Markdown and code files up to 1 MB and Word (`.docx`) documents up to 20 MB, which keep their tracked changes and comments. Larger files download instead.

## Export and delete

Select records, then choose an action from the **⋯** menu:

- **Export → Records** downloads them as CSV or Excel (XLSX), including an annotations column.
- **Export → Annotations (JSON)** downloads their traces with each annotation attached to the span it was made on.
- **Export → Traces (JSON)** downloads their raw traces.
- **Delete Record(s)** archives them.
