An evaluation record normally holds your system's inputs, outputs, and scores. If your agent is also [traced](/features/tracing), you can link each trace to its record, so reviewers see every model call and tool call behind a score next to the outputs you returned.

## How linking works

`run_and_evaluate` generates a unique link ID for each testcase and passes it to your `system` function in an `options` argument. Set it on the trace as `scorecard.otel_link_id`, as a resource attribute or on the trace's root span, and Scorecard merges the trace into the record with the same ID.

## Set it up

Instrument your agent with any [tracing method](/features/tracing#choose-a-method), then accept `options` in your system function and put the link ID on the trace. These examples assume `PROJECT_ID`, `TESTSET_ID`, and `METRIC_ID` hold your own IDs.

<Tabs>
  <Tab title="wrap() or OpenTelemetry">
    Open a span around each testcase and set the attribute on it. Model calls made inside the span become its children.

    <CodeGroup>
    ```python Python
    from openai import OpenAI
    from opentelemetry import trace
    from scorecard_ai import Scorecard, wrap
    from scorecard_ai.lib import SystemOptions, run_and_evaluate

    scorecard = Scorecard()
    client = wrap(OpenAI())
    tracer = trace.get_tracer("my-agent")


    def system(inputs: dict, _system_version, options: SystemOptions) -> dict:
        with tracer.start_as_current_span("eval.case") as span:
            span.set_attribute("scorecard.otel_link_id", options["otel_link_id"])
            response = client.chat.completions.create(
                model="gpt-4o-mini",
                messages=[{"role": "user", "content": inputs["question"]}],
            )
            return {"answer": response.choices[0].message.content}


    run = run_and_evaluate(
        client=scorecard,
        project_id=PROJECT_ID,
        testset_id=TESTSET_ID,
        metric_ids=[METRIC_ID],
        system=system,
    )
    trace.get_tracer_provider().force_flush()  # send the last spans before exit
    ```

    ```typescript TypeScript
    import { trace } from "@opentelemetry/api";
    import OpenAI from "openai";
    import Scorecard, { runAndEvaluate, wrap, type SystemOptions } from "scorecard-ai";

    const scorecard = new Scorecard();
    const client = wrap(new OpenAI());
    const tracer = trace.getTracer("my-agent");

    async function system(inputs: { question: string }, options?: SystemOptions) {
      return tracer.startActiveSpan("eval.case", async (span) => {
        try {
          if (options) span.setAttribute("scorecard.otel_link_id", options.otelLinkId);
          const response = await client.chat.completions.create({
            model: "gpt-4o-mini",
            messages: [{ role: "user", content: inputs.question }],
          });
          return { answer: response.choices[0].message.content ?? "" };
        } finally {
          span.end();
        }
      });
    }

    const run = await runAndEvaluate(scorecard, {
      projectId: PROJECT_ID,
      testsetId: TESTSET_ID,
      metricIds: [METRIC_ID],
      system,
    });
    ```
    </CodeGroup>

    In TypeScript, `options` is passed only when your function declares it as a parameter. Don't give it a default value or use a rest parameter, or it won't be detected.
  </Tab>

  <Tab title="Claude Agent SDK">
    Start from the [Claude Agent SDK setup](/intro/claude-agent-sdk-tracing#claude-agent-sdk) and add the link ID to `OTEL_RESOURCE_ATTRIBUTES` inside `system`. `scorecard_env` (`scorecardEnv`) is the dict of tracing variables from that page.

    <CodeGroup>
    ```python Python
    import asyncio

    from claude_agent_sdk import ClaudeAgentOptions, query
    from scorecard_ai.lib import SystemOptions


    def system(inputs: dict, _system_version, options: SystemOptions) -> dict:
        env = {
            **scorecard_env,
            "OTEL_RESOURCE_ATTRIBUTES": f"scorecard.project_id={PROJECT_ID},scorecard.otel_link_id={options['otel_link_id']}",
        }

        async def ask() -> str:
            result = ""
            async for message in query(prompt=inputs["question"], options=ClaudeAgentOptions(env=env)):
                if getattr(message, "subtype", None) == "success":
                    result = message.result
            return result

        return {"answer": asyncio.run(ask())}
    ```

    ```typescript TypeScript
    import { query } from "@anthropic-ai/claude-agent-sdk";
    import { type SystemOptions } from "scorecard-ai";

    async function system(inputs: { question: string }, options?: SystemOptions) {
      const env = {
        ...process.env,
        ...scorecardEnv,
        OTEL_RESOURCE_ATTRIBUTES: `scorecard.project_id=${PROJECT_ID},scorecard.otel_link_id=${options?.otelLinkId}`,
      };

      let answer = "";
      for await (const message of query({ prompt: inputs.question, options: { env } })) {
        if (message.type === "result" && message.subtype === "success") answer = message.result;
      }
      return { answer };
    }
    ```
    </CodeGroup>

    Pass `system` to `run_and_evaluate` as in the first tab. The Agent SDK can emit several traces per conversation; they share the link ID and session ID, so they merge into the same record.
  </Tab>
</Tabs>

Without the helper, pass your own unique `otel_link_id` (`otelLinkId`) to `records.create` and set the same value on the trace.

## What the linked record shows

- Scoring starts when the record is created and reads the outputs your system returned, unless the trace arrives first (see the note below).
- When the trace arrives, usually within a minute, the record shows it in the **Conversation** and **Debug** tabs, and your returned outputs move to the **Output** tab.
- The link ID is all Scorecard needs to join them. The record stays in the run's project, whatever project ID the trace carries.

<Note>
  After a trace is linked, the record's inputs and outputs hold the trace, and your returned values are kept under `outputs.metadata.sdk_outputs`. A metric that reads `{{ outputs.<field> }}` finds nothing once that happens, which matters when you re-score, or when a trace is ingested before its record. For metrics on linked records, use `{{ allOutputs }}` or `{{ outputs.metadata.sdk_outputs.<field> }}`.
</Note>

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| The record never shows a trace | Check that the trace arrives at all on the [Records](/features/records) page. Flush the tracer before your script exits, and make sure the link ID is on the root span or resource, not only on a child span. |
| Each testcase shows up twice, once as a trace record | The link ID didn't reach the trace. In TypeScript, check that `system` declares the `options` parameter. |
| Traces from one testcase merge into another | Use the link ID from each call's `options`; don't reuse one ID across testcases. |
