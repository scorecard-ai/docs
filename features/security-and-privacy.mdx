## Data Encryption and Data Security

Scorecard AI takes extensive measures to ensure the confidentiality, integrity, and overall security of your data.

* **Encryption:** Data is stored encrypted (using the AES-256 standard) and transmitted encrypted (using HTTPS/TLS protocols). This protects sensitive details such as access tokens and confidential information.
* **Data Erasure:** We erase data upon request or when it reaches its designated retention period, ensuring that outdated information isn’t stored unnecessarily.
* **Physical Security:** Our cloud service providers ensure the physical security of the infrastructure where your data is stored using industry-standard encryption.

## Access control

* **Organization isolation:** Every project, record, and API key belongs to one organization, and a key only grants access to its own organization's data.
* **Roles:** Members are admins or members, and only admins can create API keys or assign review work. See [Organizations and projects](/features/projects#members-and-roles).
* **Single sign-on:** Enterprise customers can require SAML SSO through their identity provider. See [SSO](/features/enterprise-authentication).
* **API keys:** Keys are created by admins, shown once, and can be revoked at any time from **Settings**.

## Data you send to Scorecard

* **Traces and records** contain whatever your instrumentation captures, which often includes prompts, model outputs, and tool inputs and outputs. You can turn off content capture in most instrumentation, for example by leaving out the `OTEL_LOG_*` variables for Claude Code.
* **Personal data** isn't detected or redacted automatically. Redact it before you send traces or records if your policies require it.
* **Scoring:** when an AI metric scores a record, Scorecard sends the record's content to the judge model's provider, using your organization's [provider key](/features/custom-provider) if you've added one.
