A **testset** is a collection of **testcases** that you run your agent on, so every version is measured against the same inputs. Each testcase holds the inputs your agent receives and, optionally, the expected output that metrics compare against.

## Create a testset

On your project's **Testsets** page, click **New Testset** and give it a name and description. Check **Add example Testcases?** to have Scorecard write three starter testcases from the description.

You can also create testsets by [importing a transcript](#import-from-a-transcript) or [from code](#manage-testsets-from-code).

<a id="understanding-input-fields" />

## Define the schema

A testset's schema lists its fields. Each field has a type (**String**, **Number**, **Boolean**, **Object**, or **Array**) and a role:

| Role | Used for |
| --- | --- |
| **Input** | Sent to your agent. Match the names and shape your agent expects. |
| **Expected outputs** | The ideal result. Metrics read these fields as `{{ expected.<field> }}`. |
| **Metadata** | Stored with the testcase for analysis, such as difficulty or source. Not sent to your agent or used in scoring. |

Open **Edit Schema** from the testset's menu to add, remove, or change fields in the **Fields** tab, or edit the JSON Schema directly in **Raw Schema**. Every testset needs at least one input. Existing testcases are kept and checked against the new schema.

## Add testcases

### In the UI

Click **Add Testcase** on the testset page and fill in the fields. You can edit any field later directly in the testcase table.

<a id="importing-from-a-file" />

### Import from a file

Choose **Upload Testcases** from the testset's menu and drop a CSV, TSV, JSON, or JSONL file. Columns are matched to schema fields by name; the examples below fit a new testset's default fields. A row whose `id`, `testcase_id`, or `testcaseId` matches an existing testcase updates that testcase instead of adding a copy, so you can edit a testset in a spreadsheet and upload it again. This works when the ID column isn't one of your schema's fields and every ID in the file is unique.

<CodeGroup>
```csv testcases.csv
userQuery,context,ideal
"How do I cancel my order?","Order placed 1 hour ago","You can cancel within 2 hours from Orders > Cancel."
"Where is my package?","Shipped yesterday","Use the tracking link in your shipping email."
```

```jsonl testcases.jsonl
{"userQuery": "How do I cancel my order?", "context": "Order placed 1 hour ago", "ideal": "You can cancel within 2 hours from Orders > Cancel."}
{"userQuery": "Where is my package?", "context": "Shipped yesterday", "ideal": "Use the tracking link in your shipping email."}
```
</CodeGroup>

### Generate with AI

Select up to three testcases as examples, click **Generate**, and optionally describe what to cover. Scorecard writes 1 to 10 new testcases that follow your schema, and you review them before they're saved.

### Import from a transcript

**Import from transcript** on the Testsets page takes an agent session transcript, such as a Claude Code `session.jsonl`, up to 2 MB. Scorecard finds the moments where the agent should have acted differently and turns each one into a testcase in a new testset, with the prompt as the input and the expected behavior as the expected output. Add optional guidance to focus the analysis. It takes a few minutes and keeps running if you close the dialog.

## Manage testsets from code

Create a testset with a JSON Schema and a field mapping, then add testcases in batches of up to 100. These examples assume `PROJECT_ID` holds your project ID:

<CodeGroup>
```python Python
from scorecard_ai import Scorecard

scorecard = Scorecard()

testset = scorecard.testsets.create(
    PROJECT_ID,
    name="Support questions",
    description="Common, edge, and risky support questions.",
    json_schema={
        "type": "object",
        "properties": {
            "question": {"type": "string"},
            "idealAnswer": {"type": "string"},
            "category": {"type": "string"},
        },
        "required": ["question"],
    },
    field_mapping={"inputs": ["question"], "expected": ["idealAnswer"], "metadata": ["category"]},
)

scorecard.testcases.create(
    testset.id,
    items=[
        {"json_data": {"question": "How do I reset my password?", "idealAnswer": "Settings > Security > Reset password.", "category": "account"}},
        {"json_data": {"question": "Can I get a refund after 30 days?", "idealAnswer": "No. Refunds are available for 30 days.", "category": "billing"}},
    ],
)
```

```typescript TypeScript
import Scorecard from "scorecard-ai";

const scorecard = new Scorecard();

const testset = await scorecard.testsets.create(PROJECT_ID, {
  name: "Support questions",
  description: "Common, edge, and risky support questions.",
  jsonSchema: {
    type: "object",
    properties: {
      question: { type: "string" },
      idealAnswer: { type: "string" },
      category: { type: "string" },
    },
    required: ["question"],
  },
  fieldMapping: { inputs: ["question"], expected: ["idealAnswer"], metadata: ["category"] },
});

await scorecard.testcases.create(testset.id, {
  items: [
    { jsonData: { question: "How do I reset my password?", idealAnswer: "Settings > Security > Reset password.", category: "account" } },
    { jsonData: { question: "Can I get a refund after 30 days?", idealAnswer: "No. Refunds are available for 30 days.", category: "billing" } },
  ],
});
```
</CodeGroup>

The field mapping needs all three keys; use `[]` for a role with no fields. Schemas support the JSON Schema keywords `type`, `properties`, `required`, `additionalProperties`, `items`, `enum`, and `anyOf`. Testcases that don't match the schema are still saved, with their validation errors.

Then run on the testset with `run_and_evaluate(..., testset_id=testset.id)`. See [Runs](/features/runs).

## Other actions

- **Duplicate** a testset to make a variant with the same schema, or **Copy to** another testset to copy selected testcases.
- **Move to Project** moves a testset to another project.
- **Export as CSV** or **Export as Excel (XLSX)** from the testset's menu.
- Deleting testcases removes them permanently. Deleting a testset archives it.

## Design tips

- **Start small and real.** 10 to 20 testcases that cover common requests, edge cases, and risky ones tell you more than hundreds of near-duplicates.
- **Grow from failures.** When you find a bad record on the Records page, add a testcase for it so the fix stays fixed.
- **Keep sets for different jobs.** A small set for every pull request, a larger regression set nightly, and a must-pass set for critical behavior.
- **Leave out secrets and personal data.** Testcases are visible to everyone in your organization.
