Scorecard ingests [OpenTelemetry](https://opentelemetry.io) traces. Each trace, or each session of related traces, becomes a record on the [Records](/features/records) page, where you can replay the conversation, inspect every span, ask questions about the trace, and score it with [metrics](/features/metrics).

New to tracing in Scorecard? Start with the [Tracing quickstart](/intro/tracing-quickstart).

<a id="agent-frameworks" />

## Choose a method

Pick your stack on the [Integrations](/integrations/overview) page. Every option sends standard OpenTelemetry traces to the endpoint below.

## Endpoint

| Setting | Value |
| --- | --- |
| Traces URL | `https://tracing.scorecard.io/otel/v1/traces` |
| Base URL, for exporters that append `/v1/traces` | `https://tracing.scorecard.io/otel` |
| Protocol | OTLP over HTTP, protobuf or JSON. gRPC isn't supported. |
| Authentication | `Authorization: Bearer <SCORECARD_API_KEY>` |

Scorecard stores traces only. Turn off OpenTelemetry metrics and logs exporters that point at this endpoint.

## Route traces to a project

Set the resource attribute `scorecard.project_id` to your numeric project ID, the number in the project URL:

```bash
export OTEL_RESOURCE_ATTRIBUTES="scorecard.project_id=314"
```

| `scorecard.project_id` is | The trace goes to |
| --- | --- |
| The ID of an active project in your organization | That project |
| Missing, or not a number | Your organization's oldest project |
| A number that doesn't match an active project in your organization | Nowhere: the trace is dropped |

Scorecard reads `scorecard.*` attributes and the session ID from a single span, the first one in the trace that has any of them, plus its resource. Set them all together, as resource attributes or on the root span. Tags are the exception: Scorecard reads them from every span.

## Group traces into sessions

A chat agent produces one trace per turn. Give every trace in a conversation the same session ID and Scorecard merges them into one record.

Set `session.id` on the root span of each turn, using the conversation or thread ID your app already has. Claude Code and the Claude Agent SDK set it for you. `scorecard.session_id`, as a resource or root span attribute, works too; use one of them consistently.

<CodeGroup>
```python Python
from opentelemetry import trace

tracer = trace.get_tracer("my-agent")

with tracer.start_as_current_span("agent.turn") as span:
    span.set_attribute("session.id", conversation_id)
    reply = run_turn(user_message)
```

```typescript TypeScript
import { trace } from "@opentelemetry/api";

const tracer = trace.getTracer("my-agent");

await tracer.startActiveSpan("agent.turn", async (span) => {
  span.setAttribute("session.id", conversationId);
  try {
    return await runTurn(userMessage);
  } finally {
    span.end();
  }
});
```
</CodeGroup>

Files your agent reads or writes can be attached to a session through the API and appear on the record. See [Attachments](/features/records#attachments).

## Set Scorecard attributes

| Attribute | Effect |
| --- | --- |
| `scorecard.tags` | Comma-separated tags for the record, for example `beta,mobile`. Set it as a span attribute. |
| `scorecard.tag.<name>` | Set to `true` to add the tag `<name>`. Use this form inside `OTEL_RESOURCE_ATTRIBUTES`, where commas separate attributes. |
| `scorecard.<anything else>` | Saved as record metadata without the prefix, for example `scorecard.env` becomes `env`. Search it with `metadata:`. |
| Any other resource attribute | Becomes a `resource.<key>:<value>` filter and an optional column on the Records page. |
| `scorecard.tracing_group_id` | Puts every trace with the same value into one run, for example a batch job. See [Score traces](#score-traces). |
| `scorecard.testcase_id` | Ties the record to a testcase by its ID. |
| `scorecard.otel_link_id` | Merges the trace into a record created by the SDK. See [Link traces to runs](/features/sdk-tracing). |

Tags can be up to 64 characters of letters, digits, spaces, and `_ - : .`, with up to 50 per record. Tags added through tracing are labeled **otel** in the app.

## What Scorecard reads from spans

Scorecard recognizes these conventions and uses them to show inputs, outputs, models, tokens, and tool calls:

| Source | Recognized by |
| --- | --- |
| Claude Code and the Claude Agent SDK | `claude_code.*` spans |
| OpenLLMetry, OpenInference, and LangChain | `traceloop.*`, `openinference.*`, `llm.*`, `input.value`, `output.value` |
| Vercel AI SDK | `ai.*` attributes |
| OpenTelemetry GenAI conventions | `gen_ai.*` attributes |

For your own spans, set the attributes listed in [Attributes Scorecard reads](/integrations/opentelemetry#attributes-scorecard-reads).

Cost is estimated from the model name and token counts using public model pricing, and shown with the record's duration and token count.

## Score traces

New traces aren't scored by default. To score them, select records on the Records page, click **Score Records**, and pick your metrics. AI metrics see the full trace through `{{ allInputs }}` and `{{ allOutputs }}`, which the default metric template already includes. See [Metrics](/features/metrics).

To score traces as they arrive, give them the same `scorecard.tracing_group_id` so they join one run. Score a few of its records once with **Score Records**. After that, Scorecard scores each new trace in the group with the same metrics.

## Limits and privacy

- Traces usually appear within seconds and can take up to a minute under load.
- Keep each export request under 1 MB. The SDK wrappers send one span per request.
- Spans can contain prompts, completions, and tool inputs and outputs. Turn off content capture in your instrumentation, for example the `OTEL_LOG_*` variables for Claude Code, if you don't want that content sent to Scorecard.
- Scorecard doesn't detect or redact personal data in traces. Redact it before export if you need to.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Nothing arrives">
    Look for exporter errors in your app's output:

    | Error | Cause |
    | --- | --- |
    | `401` | The API key is missing or invalid in the process that sends traces. |
    | `404` | Wrong path. Exporters and SDK wrappers use `.../otel/v1/traces`. OpenLLMetry, Claude Code, and other tools that append `/v1/traces` use `.../otel`. |
    | Connection refused or timeout | A firewall or proxy blocks `tracing.scorecard.io`. Allow outbound HTTPS to it. |
    | No error and no spans | Instrumentation started too late, the exporter uses gRPC, or the process exited before spans were flushed. |
  </Accordion>
  <Accordion title="Traces land in the wrong project">
    `scorecard.project_id` is missing, not numeric, or set only on child spans. See [Route traces to a project](#route-traces-to-a-project).
  </Accordion>
  <Accordion title="One request shows up as many records">
    Each trace becomes its own record. Open a parent span around the request so model and tool calls nest under it, or set a [session ID](#group-traces-into-sessions).
  </Accordion>
  <Accordion title="Inputs and outputs are empty">
    The spans don't carry content in a convention Scorecard reads. Turn on content capture in your instrumentation, or set the attributes in [What Scorecard reads from spans](#what-scorecard-reads-from-spans).
  </Accordion>
</AccordionGroup>
