Claude Code, and the [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk) that runs it, export OpenTelemetry traces on their own. Point them at Scorecard with environment variables and every conversation shows up as one record, with each user turn, model call, tool call, and sub-agent.

## Prerequisites

- A Scorecard API key and project ID. See the [Tracing quickstart](/intro/tracing-quickstart).
- For the Agent SDK: Python `claude-agent-sdk` 0.1.18 or later, or TypeScript `@anthropic-ai/claude-agent-sdk` 0.1.71 or later.

## Set the environment variables

<ClaudeCodeEnv />

| Variable | Purpose |
| --- | --- |
| `OTEL_EXPORTER_OTLP_HEADERS` | Authenticates with your Scorecard API key |
| `ENABLE_BETA_TRACING_DETAILED`, `BETA_TRACING_ENDPOINT` | Turn on Claude Code's detailed tracing and send it to Scorecard |
| `OTEL_LOG_USER_PROMPTS` | Includes prompt text. Without it, records show timings and tool names but no prompts. |
| `OTEL_LOG_TOOL_DETAILS`, `OTEL_LOG_TOOL_CONTENT` | Include tool inputs and outputs |
| `OTEL_RESOURCE_ATTRIBUTES` | Routes traces to your project with `scorecard.project_id` |

Leave out the three `OTEL_LOG_*` variables to send timings and structure without content.

## Claude Agent SDK

The SDK starts a Claude Code process, so that process needs the variables. Export them in your shell, or pass them in code:

<CodeGroup>
```python Python
import asyncio
import os

from claude_agent_sdk import ClaudeAgentOptions, query

scorecard_env = {
    "OTEL_EXPORTER_OTLP_HEADERS": f"Authorization=Bearer {os.environ['SCORECARD_API_KEY']}",
    "ENABLE_BETA_TRACING_DETAILED": "1",
    "BETA_TRACING_ENDPOINT": "https://tracing.scorecard.io/otel",
    "OTEL_LOG_USER_PROMPTS": "1",
    "OTEL_LOG_TOOL_DETAILS": "1",
    "OTEL_LOG_TOOL_CONTENT": "1",
    "OTEL_RESOURCE_ATTRIBUTES": f"scorecard.project_id={os.environ['SCORECARD_PROJECT_ID']}",
}


async def main() -> None:
    async for message in query(prompt="What is 2 + 2?", options=ClaudeAgentOptions(env=scorecard_env)):
        print(message)


asyncio.run(main())
```

```typescript TypeScript
import { query } from "@anthropic-ai/claude-agent-sdk";

const scorecardEnv = {
  OTEL_EXPORTER_OTLP_HEADERS: `Authorization=Bearer ${process.env.SCORECARD_API_KEY}`,
  ENABLE_BETA_TRACING_DETAILED: "1",
  BETA_TRACING_ENDPOINT: "https://tracing.scorecard.io/otel",
  OTEL_LOG_USER_PROMPTS: "1",
  OTEL_LOG_TOOL_DETAILS: "1",
  OTEL_LOG_TOOL_CONTENT: "1",
  OTEL_RESOURCE_ATTRIBUTES: `scorecard.project_id=${process.env.SCORECARD_PROJECT_ID}`,
};

// The env option replaces the process environment, so spread process.env to keep PATH and your keys.
for await (const message of query({ prompt: "What is 2 + 2?", options: { env: { ...process.env, ...scorecardEnv } } })) {
  if (message.type === "result" && message.subtype === "success") console.log(message.result);
}
```
</CodeGroup>

In Python, the variables you pass are added to the inherited environment. In TypeScript, `env` replaces it.

## Claude Code

To trace your own Claude Code sessions, or Claude Code running in CI, set the variables before `claude` starts:

- **Your shell:** export them in your shell profile.
- **CI:** set them on the job, building the header from a `SCORECARD_API_KEY` secret.
- **All your sessions:** add them to the `env` block of `~/.claude/settings.json`:

```json ~/.claude/settings.json
{
  "env": {
    "OTEL_EXPORTER_OTLP_HEADERS": "Authorization=Bearer ak_...",
    "ENABLE_BETA_TRACING_DETAILED": "1",
    "BETA_TRACING_ENDPOINT": "https://tracing.scorecard.io/otel",
    "OTEL_LOG_USER_PROMPTS": "1",
    "OTEL_LOG_TOOL_DETAILS": "1",
    "OTEL_LOG_TOOL_CONTENT": "1",
    "OTEL_RESOURCE_ATTRIBUTES": "scorecard.project_id=314"
  }
}
```

Claude Code doesn't read these settings from a repository's `.claude/settings.json`, so keep them in your user settings or environment, out of version control.

## View your traces

Run your agent or start a Claude Code session, then open the project's **Records** page. Traces appear within a minute of the process exiting. Each conversation is one record: Claude Code tags every span with a session ID, so all of its traces merge.

Open the record and click **View Full Details**. The **Conversation** tab replays the session: user turns, model replies, and tool calls with their results, with sub-agents nested under the `Agent` tool call that started them. Failed tool calls are marked with an error. **Chat** and **Debug** work as on any record; see [Open a record](/features/records#open-a-record).

## Troubleshooting

<AccordionGroup>
  <Accordion title="No records appear">
    Make sure the variables are set in the process that runs Claude Code. With the TypeScript SDK, pass them through `env`, and spread `process.env` so the process keeps its `PATH` and Anthropic credentials. Traces are sent when the process exits.
  </Accordion>
  <Accordion title="Records are in the wrong project">
    Use your numeric project ID. See [Route traces to a project](/features/tracing#route-traces-to-a-project).
  </Accordion>
  <Accordion title="Records have no prompt or tool content">
    Set `OTEL_LOG_USER_PROMPTS`, `OTEL_LOG_TOOL_DETAILS`, and `OTEL_LOG_TOOL_CONTENT`.
  </Accordion>
</AccordionGroup>
