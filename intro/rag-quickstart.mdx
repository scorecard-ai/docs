---
title: "Evaluate a RAG pipeline"
description: "Score a retrieval-augmented generation pipeline on whether answers are grounded in the retrieved context, correct, and built on the right documents."
---

A retrieval-augmented generation (RAG) pipeline can fail in retrieval, by missing the right documents, or in generation, by ignoring or contradicting them. Score each part, plus the final answer, so you know which one to fix.

<Frame caption="What each kind of RAG metric compares.">
  ![Retrieval-only metrics compare the query with the retrieved context, generation-only metrics compare the context with the response, and end-to-end metrics compare the response with the ideal response](/images/rag/4.png)
</Frame>

| Check | Compares | Example metric |
| --- | --- | --- |
| Retrieval | The query and the retrieved documents | Did retrieval return the documents that answer the question? |
| Generation | The retrieved documents and the answer | Is every claim in the answer supported by the context? |
| End to end | The answer and the ideal answer | Does the answer state the same facts as the reference? |

## 1. Return the retrieved context

Have your system return what it retrieved alongside the answer, so metrics can read both:

<CodeGroup>
```python Python
def run_system(inputs: dict, _system_version) -> dict:
    docs = retriever.search(inputs["query"], k=4)  # your retriever
    answer = generate(inputs["query"], docs)  # your generator
    return {
        "answer": answer,
        "context": "\n\n".join(doc.text for doc in docs),
        "retrievedIds": [doc.id for doc in docs],
    }
```

```typescript TypeScript
async function runSystem(inputs: { query: string }) {
  const docs = await retriever.search(inputs.query, { k: 4 }); // your retriever
  const answer = await generate(inputs.query, docs); // your generator
  return {
    answer,
    context: docs.map((doc) => doc.text).join("\n\n"),
    retrievedIds: docs.map((doc) => doc.id),
  };
}
```
</CodeGroup>

## 2. Build testcases

Each testcase needs a query and an ideal answer. To score retrieval, also list the IDs of the documents that should be retrieved.

```jsonl testcases.jsonl
{"query": "What is the refund window?", "idealAnswer": "30 days from delivery.", "relevantIds": ["policy-refunds"]}
{"query": "Do you ship to Canada?", "idealAnswer": "Yes, in 5 to 7 business days.", "relevantIds": ["shipping-international"]}
```

Map `query` as an input and `idealAnswer` and `relevantIds` as expected outputs. Include questions your documents can't answer, and check that your system says so instead of guessing. See [Testsets](/features/testsets) for importing the file.

## 3. Create the metrics

Create each AI metric on the **Metrics** page, switch its guidelines to **Advanced**, and paste the text into **Prompt Template**. Basic mode doesn't fill in `{{ ... }}` variables.

**Groundedness** (AI, Boolean). It needs no ideal answer, so it also works on testcases you haven't labeled:

```text
Context given to the assistant:
{{ outputs.context }}

Answer: {{ outputs.answer }}

Pass if every claim in the answer is supported by the context. Fail if the answer states anything the context doesn't support.

{{ gradingInstructionsAndExamples }}
```

**Answer correctness** (AI, Integer 1-5):

```text
Question: {{ inputs.query }}
Answer: {{ outputs.answer }}
Ideal answer: {{ expected.idealAnswer }}

Score 5 if the answer states the same facts as the ideal answer, and 1 if it contradicts it or misses the point. Wording can differ.

{{ gradingInstructionsAndExamples }}
```

**Retrieval recall** (Heuristic, Float). Choose **Heuristic (SDK)** as the evaluation type and paste this function into the editor. It scores the share of relevant documents that were retrieved:

```python
def handler(*, inputs, outputs, expected, **kwargs):
    relevant = set(expected.get("relevantIds", []))
    retrieved = set(outputs.get("retrievedIds", []))
    if not relevant:
        return {"floatScore": 1.0, "reasoning": "No relevant documents labeled"}
    found = relevant & retrieved
    return {"floatScore": len(found) / len(relevant), "reasoning": f"Retrieved {len(found)} of {len(relevant)} relevant documents"}
```

The **Hallucination Detection** and **Source Attribution Quality** [templates](/features/metrics#start-from-a-template) are good starting points too.

## 4. Run the evaluation

Run your system on the testset with the three metrics, as in the [Evaluation quickstart](/intro/sdk-quickstart):

<CodeGroup>
```python Python
run = run_and_evaluate(
    client=scorecard,
    project_id=PROJECT_ID,
    testset_id=TESTSET_ID,
    metric_ids=[GROUNDEDNESS_ID, CORRECTNESS_ID, RECALL_ID],  # IDs of the three metrics from step 3
    system=run_system,
)
```

```typescript TypeScript
const run = await runAndEvaluate(scorecard, {
  projectId: PROJECT_ID,
  testsetId: TESTSET_ID,
  metricIds: [GROUNDEDNESS_ID, CORRECTNESS_ID, RECALL_ID], // IDs of the three metrics from step 3
  system: runSystem,
});
```
</CodeGroup>

Read the results together. Low recall with good groundedness points to retrieval; good recall with poor groundedness points to the prompt or model. Change one part at a time and run again to [compare](/features/a-b-comparison#compare-runs).

## Score production traffic

[Trace](/features/tracing) your pipeline so each request shows its retrieval and generation steps. Traced records hold the whole trace rather than named output fields, so score them with a metric that reads `{{ allInputs }}` and `{{ allOutputs }}`, such as the Hallucination Detection template. To score every request as it arrives, see [Score traces](/features/tracing#score-traces).
